# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

Requires Python >= 3.11. No runtime dependencies; `pytest` is the only dev tool.

```bash
pip install -e .          # optional: pytest finds src/ via pythonpath in pyproject.toml
pip install pytest
pytest                    # run all tests
pytest tests/skape/test_models.py::test_idea_rejects_invalid_status   # single test
```

There is no linter or formatter configured.

## Architecture

The `src/` layout package `commando_central` currently contains one domain module, `skape`, an in-memory idea tracker (the "Skape MVP"). It is developed test-first: tests under `tests/skape/` mirror the modules in `src/commando_central/skape/`.

- `models.py`: the `Idea` dataclass (`slots=True`). `__post_init__` trims title and description, rejects an empty title and normalizes status (lower-cased, must be in `VALID_STATUSES`: draft, active, completed, archived). `id` (uuid4 string) and `created_at` (UTC) are generated by default factories.
- `service.py`: `SkapeService` keeps ideas in a `dict[str, Idea]` keyed by id, with no persistence. `IdeaNotFoundError` subclasses `KeyError`.
- The public API is re-exported from `skape/__init__.py` and the top-level `commando_central/__init__.py`. Keep both in sync when adding public names.

Status validation exists in two places: `Idea._normalize_status` runs only at construction, and `SkapeService.change_status` repeats the check because it mutates `idea.status` directly, which bypasses `__post_init__`. Any code that changes status after creation must validate the same way.

Tests match on error message text (`"Idea title cannot be empty"`, `"Invalid idea status"`, `"was not found"`), so changing those messages breaks tests.

The README states that the MVP deliberately excludes a web UI, database persistence, authentication, external APIs and a CLI. Planned next steps are a CLI, SQLite persistence, and project/task entities.
